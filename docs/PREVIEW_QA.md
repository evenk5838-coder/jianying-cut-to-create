# 独立新版检查结果

2026-09-24。此报告只对应 `codex/feature-led-preview` / 4174，本轮没有上线。素材方向仍等待用户确认，不能把候选页当成已经接入主体验。

## 条件与结果

- Apple M1 Pro（8 核）、16 GB、macOS arm64；Node 24.18。
- Chrome 153.0.8010.53 / Playwright，生产构建预览；桌面 1440×900，手机 390×844，补查 360×640。
- Codex 内置浏览器 1280×720 实际打开首屏、进入体验、查看章节。视频与候选由实际文件 FFprobe、FFmpeg、浏览器加载核查。
- **没有 iOS / Android 真机、Safari、移动蜂窝网络或公网新版测试**。当前公网维持旧版，因此不把其访问结果算入新版验收。

`npm run build` 通过 TypeScript / Vite。主功能和候选页完整自动化检查 **13 / 13 通过**；人像候选更新为 P3 / P4 后，候选播放与手机布局复验也已通过。

## 性能：目标尚未完全达到

14 秒连续前进并倒退，DPR 2；手机另加触屏和 4× CPU 限速。实际 rAF 调度结果：

| 条件 | 平均帧率 | P95 帧间隔 | 同时播放最大值 | 已访问后保留的视频源 | 主文案最大组数 |
|---|---:|---:|---:|---:|---:|
| 桌面 1440×900 | 30.79 FPS | 33.4 ms | 2 | 6 | 1 |
| 手机模拟 390×844 / 4× CPU | 30.71 FPS | 33.4 ms | 2 | 6 | 1 |

空白页对照约 60.55 FPS。已减少无变化的逐帧样式写入；尝试视频强制合成层没有实质改善，因此撤销。手机版保留较轻的原编码、字形转场改用简单遮罩，没有新增粒子或 WebGL。**持续播放与滚动同时发生时仍未达到接近 60 FPS 的原目标**，不以“滚动停帧”换取测试数字，也不降低明确保留素材的清晰度。最终选定素材后仍需复测完整版本；不能将旧版暂停播放时约 60 FPS 的数字用于本版。

访问过的 6 个视频 src 保留用于快速倒退，离屏媒体暂停；这与首屏一次加载全部不同。见 [performance.json](qa/feature-preview/performance.json)。这些是本机浏览器条件的滚动调度数据，不是视频本身的帧率，也不代表真机 GPU 表现。

## 冷启动

Chrome CDP 冷缓存，4 Mbps 下载、1 Mbps 上传、150 ms 延迟，本地服务，无 CPU 限速：桌面 LCP 0.664 s / 视频首帧就绪 1.332 s；手机 LCP 0.652 s / 视频首帧就绪 1.138 s。两端初始仅一个视频 src，未请求后续章节。见 [load.json](qa/feature-preview/load.json)。这不是公网或真实手机网络测量。
